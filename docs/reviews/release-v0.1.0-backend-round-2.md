## Smallest valid extension

Add an explicit, opt-in two-phase mode to acceptance/finish and document it in the helper contract. Preserve current behavior for unstaged runs. A contract change alone cannot make the existing implementation enforce this procedure.

1. Add a validated acceptance phase field with only `pre-merge` and `post-merge` values, defaulting to pre-merge for compatibility. Keep required=true for every current check. Assign workflow/readme/audit/coverage to pre-merge and native-bundles/release/cleanup to post-merge. Reject unknown phases and bind the complete manifest obligations, SPEC and RELEASE-CONTRACT hashes into the pre-merge receipt. Do not allow arbitrary unchecked omission lists or evidence mutations to silently change the frozen plan.
2. Add `finish --phase pre-merge`: enforce all existing receipt, clean source, configured check, open-PR/head/body/state gates and all pre-merge required acceptance. Record explicit pending required post-merge IDs. Suppress apply-cleanup in this mode; any housekeeping inspection is advisory and must not delete or force premature adoption. Persist a distinct immutable pre-merge receipt with repository, PR, head SHA, source fingerprints and frozen contract/manifest identity. Return `COMPLETE pre-merge ...`, with overall completion explicitly false. Update RELEASE-CONTRACT to define this phase-qualified COMPLETE as the merge prerequisite. Never describe it as completed release work.
3. Add `finish --phase post-merge` (or an equivalently validated additive completion subcommand): require the prior pre-merge receipt and unchanged obligations; verify that exact PR is MERGED into main and bind its actual merge SHA to a clean root checkout on main. Validate merge-result source fingerprints against approved source; relevant changes invalidate the prior checks and require the review/check/PR cycle, rather than accepting mere ancestry. Handle squash/rebase merge identity explicitly; a changed commit ID with identical approved contents need not fabricate provenance. Revalidate every required acceptance row at final source, including pre-merge rows and real post-merge evidence. Preserve the pre-merge receipt and write final FINISHED.json only after all required checks pass, recording both SHAs, PR, release and cleanup evidence. This mode must not invoke the existing OPEN-only PR check or repeat destructive housekeeping after cleanup evidence was recorded.

The final phase can use the existing acceptance recorder for real clean-source command/review reports; phase scheduling needs new enforcement, not a weaker recorder. Source fingerprints alone cannot prove external release/cleanup state: reports must contain observed release URLs/run IDs and exact merged build SHA, public stable tag/assets/hashes/inventories/smoke results, and actual cleanup actions/preservation inventories. Recheck external state at finalization. Evidence must remain outside deleted checkouts. If evidence documents are committed into scoped source, record after those commits and refresh affected checks; do not create a perpetual self-invalidating report edit cycle.
